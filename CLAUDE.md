# Craft (npm package: eshop-capacitor)

The product is **Craft**, not "eshop": app id `com.eshop.atelier` (rrobin build) or `ke.craft.app` (craft.ke build). Read `ABOUT_CRAFT.md` first. It covers what the app does, deployments, payments and what is still open. When a document disagrees with the code, the code is right.

Offline-first: the till must keep working with no internet and sync later. M-Pesa is handled outside the app core; payments go through Paystack.

## Never read, never edit
- `www/` : GENERATED by `vite build` (`emptyOutDir`). Edit the source, then rebuild.
- `cloudflare/.wrangler/`, `.wrangler/` : local DB/cache state
- `archive/` : retired code (old M-Pesa listener and UI). Do not modify.
- `docs/engine/` : retired theme-fill plan. Do not follow it. Litrus Mixer is the only website editor.
- `www/theme-packages/`, `www/official-site/` : legacy. Ask before touching.
- `.agents/`, `node_modules/`, `.claude/worktrees/` (old copies of the project)

## Size rules (these keep you fast, please follow them)
1. **Never open a whole code file over ~600 lines.** Use `grep -n` to find the spot, then read a line range (about 150 lines around it). `cloudflare/worker.js` is about 9,300 lines.
2. **New and touched modules stay under ~400 lines**, one responsibility each. Several are over today (`src/app/studio-workspace-load.js`, `studio-business-cloud.js`, `src/screens/till/overview.js`); do not make them bigger.
3. **No new `window.Eshop*` globals.** Use `import`/`export`. Existing globals stay until the code that uses them is moved.
4. Each module exports a small, named API. Cross-module access goes through those exports only.
5. Plan first for anything touching more than 3 files. Write the plan, wait for my OK.

## The loop for every change
1. Find the code with `grep`, read only the relevant lines.
2. If it lives in a large file, **extract it first** into its own module in a separate step: move the code verbatim, no behavior change, wire the import, remove the old copy.
3. Run `npm run test:boot` and `npm run test:pos` after the extraction. Commit only if green.
4. Then make the actual change in the small module, run the tests again, commit.
5. One feature per commit. Commit before starting each extraction so it is easy to undo.

Keep screens as modules inside the single app, never separate HTML pages: separate pages would reload the JS and the SQLite database on every navigation and break the Android back-button handling in `src/back-button.js`. Watch for inline `onclick="..."` handlers and shared top-level variables when moving code.

## Ask me first
- Any change to payments (Paystack), accounts, or sync logic
- Database changes: add a **new numbered migration**, never edit an existing one
- `npm run cf:deploy`, `cf:craftke:deploy` and the `cf:*:d1:migrate:remote` scripts (these touch production). Never run them yourself.
- Deleting files, or adding a dependency
